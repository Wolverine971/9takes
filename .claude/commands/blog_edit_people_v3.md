# Resolve findings and finish the article

Read the request, standard, evidenceSchema/resolutionSchema, supplied draft, evidence, baseline, all independent reviews, and machine checks. On a repair run also read the prior verification and resolution. Do not invoke legacy editing, metadata or grading commands.

Work through the machine checks first (`checks`; on a repair they sit under `machine_checks`). Every `must_fix` item is something the publisher or lint will reject: fix each one. Every `quote_check` miss needs one of three outcomes: the wording corrected against the saved source text, the source text saved to `source_cache_dir` so the quote can be found, or the line rewritten as paraphrase. `advisories` (house voice, page shape, length) are to be acted on unless doing so would break a quotation or a protected passage; say which you left and why in the resolution. When the article is over length, cut repetition before adding anything: fixes should replace text, not stack on it.

Adjudicate every finding. Fix supported concerns, reject unsupported preferences with reasons, preserve distinctive strengths. Preserve the contribution of protected passages, or justify correcting/removing a false detail. Do one coherent edit that resolves reasoning, evidence, structure and pacing together. Keep the house voice from the standard: a committed type answer, the triad and core emotion first, the rival in its own "Why not Type N?" section, plain conversational sentences and varied paragraph length. A reviewer's request to hedge the type answer is a preference to reject; a reviewer's evidence against the type belongs in the "Why not" section, answered. Any sentence you add that claims an absence ("names no one", "never said") must be checked against every source the claim cites. Do not repeatedly paraphrase the same thesis. If foundational evidence is insufficient, mark the evidence insufficient_evidence with concrete research tasks instead of smoothing over the gap.

Reconcile metadata after substantive editing: supported titles, descriptions, FAQ answers and anchors, citations, facts. If machine checks report `missing_cluster_tag:<field>`, add the best-fitting tag from the standard's cluster tag table to `type`. Do not manufacture birthdays. Preserve baseline date, lastmod, published, person and loc. New drafts remain unpublished. Resolve every inherited production_pretext blocker explicitly in prior_blockers; only clear a blocker in the output after its evidence-backed resolution. Do not set grades or release metadata.

Write the three requested outputs: edited Markdown, evidence JSON and resolution JSON. Continue the same evidence/claim/source IDs, append any newly opened evidence, remove unused claims, and update every exact passage. Return every original review finding in decisions, even on repair. Carry justified prior decisions forward and add the fixes requested by verification. Record each protected passage and inherited blocker. Do not edit inputs or the live draft; the runner materializes the output for independent verification.

Re-verify runs (`reverify: true` in the request): the supplied draft is the article as it stands now, and when `owner_edited` is true the owner changed it by hand after the last verification. The owner's wording, structure and type call are decisions: do not revert or restyle them. Rebuild the evidence inventory to match the text as it stands (update every passage, add claims for new assertions and open their sources, drop claims no longer in the text). Then fix only what the prior verification's findings, the listed blockers and the machine checks still require. If an owner change rests on nothing you can open, leave the sentence, say so in the resolution, and let the verifier rule. Carry forward every prior decision.

Open cases: preserve `profile_format`, the `open_case` record and the required `## What would settle it` section. Keep every title, description and FAQ at "leading read" strength. Keep the evidence's `confidence` honest; never raise it to make the article read more decisively.
