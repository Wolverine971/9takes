# Research an evidence-first people profile

Read the stage request, its standard_file, and the evidenceSchema in contract_file. Follow only the v3 people-profile workflow; do not invoke legacy creator/prep/review commands.

Read the supplied baseline, research_notes, prior_evidence and prior_findings when present as leads. prior_findings is what the last run's jury and verifier found wrong, plus its open research tasks: start there, so this run does not repeat the same gaps. If research_notes opens with an "Owner type decision" block, test that type as the leading hypothesis; if the evidence cannot support it, hold with `insufficient_evidence` and say why instead of switching types. Existing v3 evidence is a durable source record: preserve useful IDs, recheck relevant sources, and extend it rather than rediscovering everything. Gather neutral evidence before assigning or confirming a type. Search for substantial primary sources and named testimony, open them, inspect surrounding context, and record locators and source independence. Read enough long-form material to test the motivation across contexts and time. Search snippets alone do not establish access or verification.

Save what you open. For every source you open, write its text to the request's `source_cache_dir` as `<source id>.txt` (captions as `<source id>.vtt`): the raw article text or transcript as fetched, never notes or a summary. That folder is outside the repository because the repo is public; do not copy full source text into the run directory or anywhere in the repo. The runner searches every quotation in the article in these files, and the reviewers and verifier read them, so a source with no saved text has to be fetched again by every later stage and is the most common reason a finished article is held. When a fetch fails, try the known workarounds (plain curl with a browser user agent, `https://r.jina.ai/<url>`, the Wayback `id_` raw path, `whisper-cli` on downloaded audio) before recording `access: "unavailable"`.

Then build and challenge the type hypothesis: supporting claims, counterevidence, strongest alternative, discriminator, unexplained behavior. Consider circumstance, work incentives and public performance. Check current accuracy without requiring a news paragraph. Flag sensitive allegations, contested typing, difficult historical sources and changes to a previous thesis honestly.

Write only evidence.json to the requested output path. Populate every schema field. During research, claim.passage may be empty. Use insufficient_evidence and specific research_tasks if the leading type lacks a defensible discriminator or essential evidence cannot be verified. A hold is a successful research outcome. Never invent evidence, quote locators, source access, confidence, or specificity to satisfy the schema. Do not write the blog in this stage.

Open cases: if no defensible discriminator exists AND the subject meets the standard's open-case eligibility (adult, early public career with a record that is thin because it is young, research genuinely tried), write `status: "ready"` with `profile_format: "open_case"`, `risks.contested_typing: true`, `confidence` low or medium, and a complete `open_case` record (`reason`, `live_alternatives`, at least two concrete `settle_signals`, `next_review` date). Do not use this to avoid research on a deep record; that stays `insufficient_evidence`. If a previous open case now has a real discriminator, return to `profile_format: "standard"`.
